AgentTracker — Design Notes
Updated: October 14, 2026

PURPOSE AND SCOPE
Track a user-launched AI agent in real time through a browser dashboard:
what it is doing, where it is working, and whether it is active or idle.
Track commands, tool calls, and file operations. Start with one agent and
one project directory. The project is in planning; designs below are
proposals unless identified as requirements.

FILESYSTEM MAP
Use an expandable tree of directories and files as the location map.
The original idea was the tree command; a structured scan is proposed for
internal storage. Record path, entry type, modification time, and size.
Keep the map current through filesystem notifications and periodic scans;
make hidden files and exclusions configurable.

ACTIVITY AND LOCATION MODEL
Capture agent/session/activity IDs, action or command, working directory,
known target paths or external resources, start/end times, status, result
(e.g., exit code), and evidence source.

Expected behaviors:
- Start; explore/search; read; create/edit/move/delete files.
- Execute commands, tests, builds, or external tool calls.
- Process a model step when reported; wait for input; become idle.
- Complete, fail, or cancel.

Working directory and target resources are distinct. For example:

/project/                  <- command working directory
|-- src/main.py            <- known read target
`-- output/                <- known write target

Show all concurrent activities. Retain the last known location when idle
or waiting; show external resources alongside local context.

EVIDENCE RULES
- File timestamps reveal changes, but do not identify who made them.
- Attribute activity using agent events or supporting observations;
  label inferences and unattributed filesystem changes clearly.
- Command text alone does not establish every file accessed.
- Silence means no recent activity observed, unless idle is confirmed.
- Mark disconnected tracking as stale and show the last update time.

BROWSER DASHBOARD (PREFERRED INTERFACE)
+----------------------+-------------------------------------+
| Filesystem tree      | Agent status and last update        |
| Working-dir marker   | Current command/tool, duration,     |
| Active target paths  | execution directory, and result     |
|                      +-------------------------------------+
| Select a path to     | Activity timeline                   |
| inspect its activity | Running, completed, failed actions  |
+----------------------+-------------------------------------+

Highlight active files and expand their parent directories. Keep multiple
active locations visible and retain completed actions in the timeline.

PROPOSED ARCHITECTURE
Agent runtime/tool events -------+
                                v
                         Tracker service
Filesystem/process data ------> Activity model + current state
                                |
                                | Initial map + live updates
                                v
                         Browser dashboard

Run the service on acn01, listening on localhost. Access it from the user's
computer through an SSH tunnel.
